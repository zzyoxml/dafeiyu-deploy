# 自建插件的设计与踩过的坑

这 6 个插件不在上游，是本地部署时按需求新写的。
每个都记录了「为什么这么写」和「踩过什么坑」，避免后人重踩。

---

## dsh-sing · 点歌 AI 翻唱

### 流程

```
点歌 "全球变冷" 60秒
  ↓ yt-dlp 搜索 B 站，取第一条
  ↓ ffmpeg 截取 60 秒
  ↓ demucs htdemucs --two-stems=vocals   分离人声/伴奏
  ↓ RVC cover.py（contentvec + rmvpe + liuying.pth）  换成人声音色
  ↓ ffmpeg amix 混合回伴奏
  → 发语音
```

CPU 上 60 秒的歌约 3.5 分钟（demucs 是大头）。

### 缓存（关键设计）

用户要的是「唱过的歌再点，直接秒发」。为此：

**缓存键是纯语义的**：`md5(歌名|模式|时长|起点|变调)`，**不含音源标题**。

第一版把音源标题也算进键里，结果是「必须先联网搜歌拿到标题才能命中」——
每次点歌仍要多花 5-8 秒搜索，缓存提速打了对折，而且播种时容易只存一份、
另一份查不到。改成纯语义后命中路径完全离线，实测 0.99ms。

**淘汰策略**：LRU，按 `last_used` 升序删，上限 100 首（`DSH_SING_CACHE_MAX`）。

**语义去重**：同 `(歌名,模式,时长,起点,变调)` 的多条记录，入库时删旧留新，
避免同首歌存两份音频。

### 踩过的坑

1. **`CommandFilter` 不认 @ 前缀**
   NapCat 把 `@小鲸鱼 /唱歌 全球变冷` 合成一个 Plain 段，
   `message_str` = `@小鲸鱼 /唱歌 全球变冷`，
   而 `CommandFilter` 内部判断 `startswith("/唱歌 ")` → 永远不成立。
   改用 `@filter.regex`，自带 `(?:@\S+\s*)?` 前缀容忍。

2. **`MessageChain` 导入路径**
   不在 `astrbot.api.message_components`，在
   `astrbot.core.message.message_event_result`。

3. **B 站 HTTP 412**
   需要种子 cookie（`buvid3`/`buvid4`）+ `search.bilibili.com` Referer。

4. **`start` 被 clamp 后入库，下次查不到**
   用户传 `start=0`，但歌曲太短被修正成 `start=12`，
   入库用了 12，下次 `start=0` 就查不到。修复：入库用**调用方原始请求值**。

## dsh-voice-liuying · 流萤音色语音

### 设计

普通回复按 20% 概率自动出语音。取 Edge TTS 做底（免费、无需 key），
再过 RVC 换成流萤音色。带磁盘缓存（同文本不重复合成）。

### 为什么不用 dsh-voice 现有的链路

`dsh-voice` 是上游插件，主打 Fish Audio / 悟声，走的是云端 API，
音色不是流萤。所以另写一个只管「流萤 + Edge」的轻量插件。

### 踩过的坑：Edge TTS 恒返 403

```
WSServerHandshakeError: 403
url=...Sec-MS-GEC-Version=1-143.0.3650.75
```

**根因**：`edge-tts 7.2.7` 发的是过期的 Chromium 版本号，
微软侧校验不过。7.3.1 才带新版本号。

**这个坑会复发**：容器 `--force-recreate` 后，
装在主环境的 `edge-tts` 会被镜像自带的 7.2.7 覆盖回去。
而 `/AstrBot/data/sing/venv` 在挂载卷上，不受重建影响，里面是 7.3.1。

**解法**：合成时**优先用 venv 的 python 子进程**，失败才回退本进程。

```python
async def _edge_tts(out_path, text) -> bool:
    if VENV_PY.exists():
        # 子进程跑 venv 的 edge_tts 7.3.1
        ...
    # 主环境兜底（通常 403）
    import edge_tts
```

## dsh-reply-guard · 限流与滞后拦截

### 两条需求

1. 普通文字一分钟最多 10 条
2. 不回超过 10 句话之前的消息

### 实现

**限流**：滑动窗口（不是固定分钟桶，避免整分钟边界突然放行 20 条）。

**滞后拦截**：给每条消息编号，记录上次回复时的序号，
`当前序号 - 上次回复序号 > 10` 且没点名 → 丢弃事件。

**例外（必须放行）**：
- 点名（`@`、`小鲸鱼`、`鲸鱼`、`肥鱼`、`大肥鱼`、bot QQ）
- 空闲超过 600 秒（多半是新会话）

### 踩过的坑

1. **`EventMessageType.ALL` 不存在**
   只有 `GROUP_MESSAGE` / `PRIVATE_MESSAGE` / `OTHER_MESSAGE`。
   所以没做独立的消息序号监听，把编号折进 `on_llm_request`。

2. **`/歌单` 后发数字 1 被别的 bot 抢答**
   群里另一个 bot 在我之后 1 秒也发了歌单，
   LLM 把 `1` 映射到它的「十年」。
   所以加了 `cmd_pick`：裸数字只认**刚发过 `/歌单` 的那个人**，10 分钟内有效。

## dsh-awake / dsh-mute / dsh-qzone

三个较小的插件，各一句话：

- **dsh-awake**：唤醒判定，决定这条消息要不要进 LLM。
- **dsh-mute**：群里说「闭嘴」立刻禁言 1 小时；解除只有主人能说；
  禁言期的消息在解除后自动从会话历史删除，避免模型接着禁言期的话题说。
- **dsh-qzone**：定时发 QQ 空间说说，素材从群聊里挑。
